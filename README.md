# gignore

Build and maintain `.gitignore` files from a library of templates, in an interactive terminal UI or from the command line.

- **Works offline.** More than 300 templates from [github/gitignore](https://github.com/github/gitignore) are built into the binary. When online, gignore also loads the catalog from [gitignore.io](https://www.toptal.com/developers/gitignore) and caches it. Together they provide more than 600 unique templates.
- **Keeps your rules.** gignore owns only a marked block in the file. Everything outside it is preserved on every update.
- **Detects your stack.** It suggests templates from the files in your project, such as `go.mod`, `package.json`, or `.vscode/`.
- **Checks your file.** `gignore check` finds tracked files that should be ignored, negations that can never match, stray whitespace, and an outdated generated block.
- **Explains rules.** `gignore explain <path>` shows which rule ignores a path and which template it came from.
- **Fits CI.** `gignore update --check` fails when `.gitignore` is out of date.
- **Installs as one file.** It's a single static binary with no runtime to install.

## Install

| Platform | Command |
| --- | --- |
| macOS, Linux (Homebrew) | `brew install kwmx/tap/gignore` |
| Windows (Scoop) | `scoop bucket add kwmx https://github.com/kwmx/scoop-bucket`, then `scoop install gignore` |
| macOS, Linux, FreeBSD (script) | `curl -fsSL https://raw.githubusercontent.com/kwmx/gignore/main/install.sh \| sh` |
| Windows (PowerShell script) | `irm https://raw.githubusercontent.com/kwmx/gignore/main/install.ps1 \| iex` |
| Debian, Ubuntu, Fedora, Alpine, Arch | Download the `.deb`, `.rpm`, `.apk`, or `.pkg.tar.zst` from [Releases](https://github.com/kwmx/gignore/releases) |
| Go toolchain | `go install github.com/kwmx/gignore/cmd/gignore@latest` |

The install scripts verify the download against the release checksums. The script puts the binary in `/usr/local/bin` when that directory is writable, otherwise in `~/.local/bin`. To choose the directory, set `GIGNORE_BIN_DIR`. To pin a release, set `GIGNORE_VERSION`.

Packages and Homebrew install shell completions and man pages. To set up completions by hand, run `gignore completion --help`.

## Quick start

To pick templates interactively, run `gignore` in your project:

```sh
gignore
```

The picker opens with templates detected from your project already selected. Press **space** to add or remove templates, then **ctrl+s** to review the diff and save.

To print rules instead, name the templates and redirect the output. This works with any command that reads from a pipe, too:

```sh
gignore node,macos > .gitignore
```

To detect templates and write the file without the picker:

```sh
gignore generate --detect -w
```

Other common tasks:

```sh
gignore add rust                  # add a template to the existing block
gignore remove jetbrains          # remove one
gignore update                    # refresh the block with the latest templates
gignore check                     # find problems
gignore explain dist/app.js       # show which rule ignores a path
gignore add -g macos vscode       # edit your global ignore file
```

## How gignore edits your file

gignore writes its rules between two marker lines and records the templates in the first one:

```gitignore
# >>> gignore start: go, node, macos
# Generated by gignore. Edits inside this block are replaced on update; add your own rules outside it.
### Go ###
*.exe
...
# <<< gignore end

# Project-specific rules (gignore keeps everything outside the block above)
.env.local
```

- Rules outside the block are never changed.
- In a file without a block, gignore adds the block at the top and keeps your existing rules below it. Git applies the last matching rule, so your rules can override template rules.
- `gignore add`, `remove`, and `update` read the template list from the start marker, so teammates don't need any other file.
- When several templates contain the same rule, gignore keeps only the first copy. It keeps a later copy when a negation (`!pattern`) appears between them, because removing it would change which files are ignored. To keep every copy, use `--no-dedupe`.
- To replace the whole file instead, use `gignore generate --replace`. gignore asks before discarding your rules.

By default, gignore writes to `.gitignore` at the repository root, even when you run it from a subdirectory. To write somewhere else, use `-o <path>`.

## Interactive picker

| Key | Action |
| --- | --- |
| Type | Search templates |
| **space**, **enter** | Add or remove the highlighted template |
| **tab**, **shift+tab** | Switch between the templates, selected, and preview panes |
| **shift+↑**, **shift+↓** | Reorder selected templates (in the selected pane) |
| **ctrl+s**, **ctrl+d** | Review the diff, edit the target path, and save |
| **ctrl+a** | Add all detected templates |
| **ctrl+r** | Switch search mode: fuzzy, exact, or regex |
| **ctrl+x** | Clear the selection |
| **ctrl+y** | Copy the generated block to the clipboard |
| **f1** | Show all shortcuts |
| **esc** | Clear the search, or quit |

In the templates list, **★** marks detected templates and `recent` marks templates you use often. You can also click a template to add or remove it, click a pane to focus it, and scroll the list and preview with the mouse wheel.

## Commands

| Command | Description |
| --- | --- |
| `gignore [templates...]` | Open the interactive picker with those templates selected. When output is piped or redirected, print their rules instead |
| `gignore generate [templates...]` | Print rules, or write them with `-w` or `-o <path>` |
| `gignore add <templates...>` | Add templates to the block |
| `gignore remove <templates...>` | Remove templates, or the whole block with `--all` |
| `gignore update` | Regenerate the block. With `--check`, exit with status 3 if it's out of date |
| `gignore untrack` | Remove tracked files that match your rules from the git index (files stay on disk) |
| `gignore list [query]` | List or search templates. Supports `--json` and `--keys` |
| `gignore show <templates...>` | Print a template's rules |
| `gignore detect` | Show which templates the project seems to need |
| `gignore check` | Report problems. With `--strict`, warnings also fail |
| `gignore explain <paths...>` | Show the rule and template that decide whether a path is ignored |
| `gignore cache [info\|refresh\|clear]` | Manage the cached online catalog |
| `gignore config [show\|init\|edit\|path]` | Manage configuration |
| `gignore doctor` | Check git, configuration, templates, and network access |

Commands that write accept `--dry-run` (`-n`) to show the diff without writing, `--diff` (`-d`) to show it and then write, and `-g` to target your global ignore file.

Template names are case-insensitive. You can separate them with spaces or commas and use aliases such as `js`, `py`, `golang`, `vscode`, or `mac`. If you mistype a name, gignore suggests the closest match.

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success |
| `1` | Error, or a cancelled confirmation |
| `2` | Invalid command-line usage |
| `3` | `check` found problems, or `update --check` found an outdated file |

## Use in CI

To fail a build when `.gitignore` is out of date or has errors:

```sh
gignore update --check
gignore check --strict
```

By default, a built-in template wins over an online template with the same name. So when all your templates are built in, the same gignore version produces the same output on every machine. To make CI skip the network, pass `--offline` or set `GIGNORE_OFFLINE=1`.

## Configuration

Settings are optional. gignore reads them in this order, and later sources override earlier ones:

1. Built-in defaults
2. User config: `~/.config/gignore/config.toml` (`%AppData%\gignore\config.toml` on Windows)
3. Project config: `.gignore.toml`, found by walking up to the repository root
4. Environment variables: `GIGNORE_OFFLINE`, `GIGNORE_API_URL`, `GIGNORE_THEME`, `GIGNORE_OUTPUT`, `GIGNORE_CONFIG`

To create a documented config file, run `gignore config init`. To create a project file, run `gignore config init --project`.

This example shows the settings people change most often:

```toml
[generate]
always = ["macos", "visualstudiocode"]   # added to every generation

[presets]
web = ["node", "macos", "visualstudiocode"]   # use as: gignore generate @web

[aliases]
tf = "terraform"

[online]
enabled = true
prefer = "builtin"   # or "online" to use gitignore.io's versions

[tui]
theme = "auto"       # auto, dark, light, or mono
```

A project's `.gignore.toml` can set `generate.templates`. The picker and `gignore generate -w` use that list by default.

For every setting, see [docs/configuration.md](docs/configuration.md).

### Your own templates

To add your own templates, put `*.gitignore` files in `~/.config/gignore/templates/`. gignore lists each file by its name, and your own templates override built-in and online templates with the same name.

## Templates and sources

| Source | Count | Availability |
| --- | --- | --- |
| Built-in, from [github/gitignore](https://github.com/github/gitignore) | 300+ | Always, including offline |
| [gitignore.io](https://www.toptal.com/developers/gitignore) | about 570, most overlapping the built-in set | Online; cached for 7 days and used when a later fetch fails |
| Your templates | any | Always |

A weekly workflow refreshes the built-in templates. The github/gitignore templates are distributed under [CC0 1.0](internal/catalog/builtin/data/LICENSE).

## Build from source

Building requires Go 1.25 or later.

```sh
cd gignore
make build      # writes bin/gignore
make test
```
